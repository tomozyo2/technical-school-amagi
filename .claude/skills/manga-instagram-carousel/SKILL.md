# 漫画をサイト＆Instagram用に仕上げる

新しい話（または差し替えた話）の1枚絵ができたら、この手順で「サイトのコマ送り表示」と「Instagramのカルーセル投稿素材」を両方仕上げる。社長から話数と絵しか伝えられなくても、この一連の作業（サイトへの反映まで）を毎回やること。

## 全体の流れ

1. 新しい絵ファイルを確認する（Readツールで開いて中身を見る）
2. サイトの本体（manga-data.js）を新しい絵に差し替える
3. `scripts/build_carousel.py` で「コマの位置」と「Instagramカルーセル」をまとめて作る
4. manga-panels.js に、3で出てきた位置の数字を登録する
5. キャプション文（説明文.txt）を確認・用意する
6. **使い終わった元絵ファイルを `manga/漫画削除予定ファイル/` に移動する**
7. 出来上がりを目で確認してから、git に登録して公開する

以下、順番に説明する。

## 1. 新しい絵ファイルを確認する

新しい話は、たいてい `manga/` 直下に日本語のファイル名（例:`3話犬の習性.png`）で置かれる。話の途中に「4話へつづく」のような次回予告が絵の中に描き込まれていることもあるので、Readツールで画像を開いて中身と話数・タイトルを確認する。

## 2. manga-data.js を差し替える

`manga-data.js` の中で、対応する話数（"number"）のオブジェクトを探し、次の3つを更新する。

- `image`: `manga/episode<話数>-<今のタイムスタンプ(ミリ秒)>-0.<拡張子>` という名前でコピーしたファイルのパス
- `imageUpdatedAt`: 同じタイムスタンプの文字列
- `title`: 新しい絵の中に描き込まれているタイトルと合わせる（例:絵に「3話 犬の習性」とあれば `"犬の習性"`）。story-archive.md（manga-character-prompt スキル）に決まったタイトルがあれば、それを優先する。

タイムスタンプは `date +%s000`（ミリ秒）で作れる。ファイルは編集前に必ずコピーしてから元ファイルは残しておく（古い絵は消さずに保持。差し替え後、site上で参照されなくなった**古い**episode画像だけは消してよい）。

## 3. コマの位置とInstagramカルーセルをまとめて作る

このスキルには、実際に使えるPythonの道具が2つ同梱されている。

- `scripts/panels.py` : 白い余白を手がかりに、コマの位置を自動で見つける（再帰的なXYカット）
- `scripts/carousel2.py` : 見つけたコマを、Instagram投稿用の緑背景デザイン（ロゴ・話数・ページ番号・スワイプ案内つき）に組み立てる
- `scripts/build_carousel.py` : 上の2つをつなげて、1回のコマンドで済ませる本体

プロジェクトのルート（`テクニカルスクール甘木サイト/`）から、こう実行する。

```
python .claude/skills/manga-instagram-carousel/scripts/build_carousel.py --src "manga/episode3-1790085227000-0.png" --ep-label "第3話" --ep-dir "3話" --out-base "manga"
```

- `--src` : 2で新しく置いた画像のパス
- `--ep-label` : カルーセル画面の右上に出す文字（`第3話` のように）
- `--ep-dir` : 保存フォルダ名。これまでの慣習に合わせて `3話` のように話数＋「話」でよい
- `--out-base` : 既定は `manga`（`manga/インスタ用カルーセル/<ep-dir>/` に保存される）

実行すると、次が自動でできる。

- `manga/インスタ用カルーセル/<話数>/01.jpg, 02.jpg, ...`（最初の1枚がタイトルカード、残りが各コマ。最後の1枚だけ「スワイプ」の案内なし）
- `manga/_確認用_<話数>_枠線.png`（自動検出したコマの位置に枠線を引いた確認用画像。**これを一度Readツールで開いて、コマがずれていないか自分の目で確認する**こと）
- 標準出力に `FRACS: [...]` という配列（manga-panels.js にそのまま貼る値）

### よくあるつまずき：タイトル帯と①のコマがくっついている話

3話・9話のように、タイトル帯（話数とタイトルの帯）と①のコマの間に白いすき間が無い絵だと、自動検出が2つを1つの箱として拾ってしまう。`build_carousel.py` にはこれを見つけて自動で直す仕組みが入っている（先頭の箱が画像の高さの30%を超えていたら、コマの黒い枠線の行を探して、そこで手動に分ける）。実行後の標準出力に「タイトル帯と最初のコマがくっついていたため、y=◯◯の黒い枠線で手動に分けた」と出たら、それが起きた合図なので、確認用画像で本当に正しく分かれているか必ず目で見る。

まれに自動の分け方でもうまくいかないことがある。そのときは `scripts/panels.py` の `profile()` を使って、怪しい範囲の黒い割合を自分で調べ、境目を手で決める（3話のときにやったやり方と同じ）。

### よくあるつまずき：コマの片側が空や海のような明るい背景で、自動検出が手前で切れる話

5話⑥コマ（ゴール前でネコが「？」となる場面）のように、コマの端のほうに白に近い明るい背景（青空・雲など）が広く続いていると、自動検出（`panels.py`）がそこを「コマとコマの間の余白」と誤解して、本当の黒枠より手前で切ってしまうことがある。**必ず `_確認用_<話数>_枠線.png` を目で見て、ピンクの枠が絵の黒い外枠にちゃんと届いているか確認する**こと。届いていないコマがあれば、そのコマの範囲だけ広げて、黒い枠線（`gray<60` が幅の50%以上を占める行・列）の位置を探し、そこまで座標を手動で広げてから、もう一度カルーセルを作り直す。

## 3.5 表紙（カバー）をサイトの1ページ目にも使う（2026-09-29決定・これからは毎回この形でOK）

Instagram用に作った「表紙」画像（キャラのアップ＋大きいタイトル、manga-character-promptスキルの「Instagram用の『表紙』プロンプト」で作るもの）は、サイトの1ページ目にも必ず追加する。手順は次の通り。

1. 表紙画像（ChatGPTの生の出力。Instagram用に1080×1350へ切り抜く前の、縦長1024×1536のもの）と、2で作った本編の絵（タイトル帯＋コマ）を、同じ横幅のまま縦につなげて1枚の画像にする（表紙が上、本編がそのまま下に続く。境目に20〜30px程度の白い隙間を入れる。隙間が無いと自動検出が表紙と本編をくっつけてしまう）。
2. つなげた画像を `manga/episode<話数>-<新しいタイムスタンプ>-0.png` として保存し、これをmanga-data.jsの`image`にする（2の手順の「差し替え」をこの結合画像で行う）。
3. `build_carousel.py` を実行すると、「表紙（1箱）＋本編のタイトル帯（1箱）＋各コマ」が検出される。
4. **manga-panels.jsに登録するときは、本編のタイトル帯の箱（表紙の次に来る、コマ縦横比が横長の小さい箱）を1つ取り除く。** 表紙にもう大きくタイトルが入っているので、その次にまた薄いタイトル帯だけのページが来ると重複して単調に見えるため。結果として「表紙→①→②→③→④…」という並びになる。
5. Instagram用のカルーセル（`manga/インスタ用カルーセル/<話数>/`）は今まで通り、表紙を1080×1350に切り抜いたものを01.jpgに、本編を2で作った絵から切り出したものを02.jpg以降に使う（サイト用の結合画像とは別物）。

## 4. manga-panels.js に登録する

`manga-panels.js` を開き、`window.MANGA_PANELS` の中に、3で得た `image` のパス（キー）と `FRACS` の配列（値）をそのまま追加・上書きする。同じ話数の古いパスのキーがあれば、それは削除する（差し替えなので、新しいパス1つだけが残る状態にする）。ファイル先頭のコメント（「登録済み」の一覧や「手で分けた」の注記）も、実態に合わせて一言足しておく。

## 5. キャプション文を用意する

`manga/インスタ用カルーセル/<話数>_説明文.txt` という名前で、次の形式のテキストを作る（無ければ新規作成、既にあれば内容が新しい絵と合っているか確認して必要なら直す）。

```
⚽第<話数>話：<タイトル>⚽
<1行目のひきの文（内容を軽くネタバレしつつ気になる終わり方に）>
<2行目のひきの文（オチや決め台詞を活かす）>

続きが読みたい人、気に入ってくれた人は、いいね！フォローをしてくれたら嬉しいです

#チロメロFC #創作4コマ #サッカー漫画 #犬のいる暮らし #ゆるふわイラスト
```

ハッシュタグと「続きが読みたい人〜」の行、絵文字の使い方（⚽と🐾）は毎回同じにする。ひきの文だけ、その話の内容に合わせて書く。

## 6. 同じ話数の古い絵ファイルを漫画削除予定ファイルへ移動する

ルールはシンプルに：**「`manga/` 直下に、同じ話数の絵が2つ以上ある」状態を作らない。** 今回2で使った絵（＝その話数でいちばん新しい絵）だけを `manga/` 直下に残し、それ以外（今回使った絵も含め、置き場所はもう `manga/episode<話数>-...` としてサイト用にコピー済みなので、`manga/` 直下にある日本語ファイル名の元絵はどれも用済み）は、話数が一致するものを全部 `manga/漫画削除予定ファイル/` フォルダへ移動する（削除はしない。あとで見返せるように残すだけ）。

「使い終わったから移動する」のではなく、**「同じ話数のファイルが複数ある状態そのものが良くない」**、というのが理由。放っておくと、次にまたその話数を作り替えたときに、`manga/` 直下のどれが最新の絵なのか分からなくなる。なので、2で使ったファイル1つだけでなく、**同じ話数のファイルが `manga/` 直下に他にも残っていないか毎回確認し、見つけたら全部移動する。**

- 移動先に**同じファイル名がすでにある**場合（前回・前々回の差し替えで残っているなど）は、上書きしないよう、移動するファイル名の末尾に今日の日付を付けて区別する（例:`3話犬の習性.png` → `3話犬の習性_2026-09-23.png`）。
- Instagram用に自動生成した `manga/_確認用_<話数>_枠線.png` は確認が終わったら消してよい（このファイルは元絵ではなく、確認用に毎回作り直されるものなので、削除予定フォルダに入れる必要はない）。

## 7. 確認してから、git に登録する

`manga/インスタ用カルーセル/` フォルダとキャプション`.txt`、確認用の枠線画像は、**Instagram投稿のための作業用ファイルであり、これまで一度もGitHubに送ったことがない**（`git log --all -- "manga/インスタ用カルーセル"` で確認できる、コミット履歴が0件）。今後もこの3つ（カルーセル画像・キャプション・確認用枠線画像）は git add しない。

GitHubに送る（＝サイトに公開反映する）のは、次の3つだけ。

- `manga-data.js`（2で編集）
- `manga-panels.js`（4で編集）
- 新しく置いた話の画像ファイル（2でコピーしたもの）

### コミット前に必ずやる安全確認

このプロジェクトの `manga/` フォルダには、過去の作業で残った「まだコミットされていない削除」が大量に溜まっている（他の話数の画像が、ローカルの作業フォルダ上では削除済み扱いなのに、GitHub上ではまだ生きていて公開サイトが参照している、という状態）。これがあるせいで、`git add -A` や、コンフリクトが起きた `git stash pop` の解決を雑にやると、**関係ない他の話の画像まで一緒に削除されてコミットされてしまい、公開サイトの他の話が壊れる。**

これを避けるため、必ず次の手順を守る。

1. `git add` は、今回触った3つのファイルだけを明示的に指定する（`git add manga-data.js manga-panels.js "manga/episode3-....png"` のように。`-A` や `.` は使わない）
2. コミットする直前に、必ず `git diff --cached --stat` を実行し、**今回のつもりの3ファイルだけ**が出ていることを目で確認する。見覚えのない他の話の画像が「削除」として混ざっていたら、それはコミットしてはいけない
3. もし混ざっていたら、`git restore --source=HEAD --staged --worktree -- <そのファイルのパス>` で、そのファイルだけを直前の状態に戻す（インデックスからも作業フォルダからも、HEADの内容に戻る）
4. きれいになったのを確認してから `git commit`、`git pull --rebase origin main`、`git push origin main` の順で進める

## 最後に

作業が終わったら、社長には次を伝える。

- サイト側は反映・公開済みであること
- Instagram用のカルーセルとキャプションは、`manga/インスタ用カルーセル/<話数>/` に置いてあり、GitHubには送っていないこと（お手元のパソコンから直接Instagramにアップロードする運用）
- 確認用の枠線画像（`manga/_確認用_<話数>_枠線.png`）でコマの区切りを確認したこと、うまく切れていない箇所があれば伝えること
